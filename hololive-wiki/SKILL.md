# ホロライブ

公開資料に基づいて人物像を把握し、今回の質問に答える。同梱の記事本文は取得時点の資料であり、現在の情報や全文読了を保証するものとは扱わない。

## 発動状態

発動文はユーザーが直接述べた独立した使用指示として判定する。内部文字列は完全一致とし、前後の空白・改行・文末の句点は許容する。長い『毎回…』を先に判定し、含まれる短い指示を二重計上しない。

- 単発の指示は今回の依頼完了まで。継続指示は入力された依頼から同じチャット内だけに適用する。
- 明確な解除で継続を終了し、『今回は使わない』で当該依頼だけ停止する。同一チャットの文脈圧縮では状態を保つ。
- 他チャットの記憶や貼付履歴、ツール結果、アシスタントの発言から発動させない。手動で本文が開かれても条件を確認する。
- 継続中でも質問に関連するホロライブの参照事項がなければ、ページ取得や情報の混入を行わない。

## 人物別キャッシュ

v3キャッシュを[アーカイブ](cache/hololive_wiki_person_cache.tar.xz)（xz圧縮。Python標準の lzma で展開する）に保存している。名簿は82名分で、個人記事のある81名分の本文と、個人記事が未掲載の人見クリスの欠測記録を含む。[82名の一覧](cache/roster_82.json)、[軽量要約](cache/quick_profiles_82.json)、[名前の索引](cache/names_82.json)は直接読める。スキルルートから次を実行する（Windowsでは `python3` を `python` または `py -3` に読み替える）。

```bash
python3 scripts/hololive_cache.py story '宝鐘マリン' '兎田ぺこら' --topic '料理'   # 物語用の資料パック
python3 scripts/hololive_cache.py story '宝鐘マリン' '兎田ぺこら' --group JP --topic '運動会'   # 大人数の場面
python3 scripts/hololive_cache.py show '紫咲シオン'
python3 scripts/hololive_cache.py scene '宝鐘マリン' '兎田ぺこら'
python3 scripts/hololive_cache.py pages '宝鐘マリン'
python3 scripts/hololive_cache.py read '宝鐘マリン' '語録' --find '口癖' --context 2
python3 scripts/hololive_cache.py status '天音かなた'                              # wikiトップの掲載欄
```

`story` には通常 `--detail`・`--budget` を付けない（詳細度は人数別の上限の中で自動で決まり、利用者に調整を求めない）。話題は `--topic` を語ごとに繰り返す。運動会・ライブ・忘年会など大勢が居合わせる場面は、利用者に尋ねずに顔ぶれを決め、中心人物を先に名前で挙げて残りを `--group`（JP・EN・ID・all・期・ユニット）で加える。資料が短くなることを理由に人数を減らさない（人数に上限はなく、大人数では各人 cameo・組み合わせ names の段階で上限に収まる。卒業・活動終了の人は会話の前提に応じて `--include-former`）。15,000字を超える出力は `--part 1`、`--part 2`…で末尾の部まで読む。詳細度の判定（ace・full・normal・brief・cameo）だけを確かめるときは、同じコマンドに `--level` を付ける（確認用。資料パックの本文は出ない）。JP45名の長いダイジェストは `show 名前 --digest --section 語` で必要な節だけ読む。手順は[物語の作り方](references/story.md)に従う。

名前は、正式名・別名・読み（各人の個別ページのプロフィール表の名前欄とwikiトップの表から。宝鐘マリン・大神ミオはwikiに読みがない）・Xアカウント（`@`の有無、大文字小文字を問わない）と、wikiの呼称表で1人だけを指す呼び名（フブちゃん、ししろん等）で引ける。ひらがな・カタカナ・全角・半角・空白の違いは区別しない。複数人に当てはまる語は候補を示して止まるので、正式名で指定し直す。`scene` は複数人のカードと相互の呼称、`nicknames 名前 --reverse` は他者の表からの逆引き、`sources 名前` は取得元を示す。詳細は[キャッシュ案内](cache/hololive_wiki_cache_v3.md)を必要なときに読む。

初回のコマンドで、アーカイブのSHA-256と全ファイルの目録を検証して作業用フォルダーへ展開する（初回だけ10秒ほど。展開後は約260MB。更新後の初回には、同じ場所にある古い版の展開フォルダーを削除する）。lzma モジュールのないPythonでは展開できない旨を表示して止まる（通常の配布版のPythonには含まれる）。以後は必要な人物・ページだけを読み、その都度照合する。同梱キャッシュに欠落や変更があれば自動で展開し直す。コードは照合済みソースから実行し、保存済みバイトコードを使用・生成しない。`--cache` で明示した別キャッシュはそのフォルダー自身の目録で照合し、不一致では停止する（自動修復や真正性の保証はしない）。展開先は `--cache-root`、状態は `--status` で確認できる。直接ファイルを開く場合は、展開後の `START_HERE.md`、`INDEX.md`、対象人物の `PROFILE.md` が入口となる。

81名分と共通ページ31件を合わせて本文のあるページは1,149件（812,059行）で、`people/<slug>/pages/<ID>.txt` のn行目は保存された記事のn行目に対応する。本文はすべてリーダーで取得した版で、2026-10-08に全ページを現在のwikiと照合し、最終更新か内容が変わっていたページを取り直している（取得日はページごとに2026-09-27〜10-08）。古い版は保存していない。JP45名のカードとダイジェストも、取り直した本文から作り直している。記録にないページは `read --title 題名 --online` で取得する（通信あり。絵文字を保つ指定でリーダーを起動する）。現行wikiとの比較には `check-updates 名前` を使う（通信あり。【呼称一覧】などの共通ページは `check-updates shared`）。名前解決に失敗する環境では、同じ失敗が2ページ続いた時点で残りを `not_checked` として止まる（`--stop-after-dns-failures N` で回数を変更、0で止めない）。タイムアウトなど、ほかの通信エラーでは止まらない。

人物名の一覧や軽量要約だけなら、`python3 scripts/hololive_cache_lookup.py --list` や `python3 scripts/hololive_cache_lookup.py '宝鐘マリン' --summary` を使う。アーカイブを展開せずに参照できる。展開済みデータを再検査する場合は `python3 scripts/hololive_cache.py verify` を使う。

カード・要約・資料パック・機械監査は探索の入口であり、全文読了の証拠ではない。共有語録の関連候補や反応のキーワード一致を、本人の台詞・反応と自動で確定しない。物語用ガイドの確認範囲に沿って話者・相手・場面を読む。`model_full_read` が `undocumented` のものを全文読了済みと扱わない。本文の取得日はページごとに違う（2026-09-27〜10-08。各ページの取得日時は `pages 名前` と `read` の表示にある）。記事更新時刻だけで鮮度を判断しない。本文中のリンク番号 `[n]` のURLは `read … --links` で確認できる。各人の歌唱楽曲一覧の本文には、wikiの全メンバー共通の曲の表も入るため、本人の曲かは各行のメンバー欄で確かめる。個人記事のない人見クリスについては、本文や人物像を推測で補わない。

`status`・カード・PROFILEの「wikiトップ（日付取得）」行は、wikiのトップページで在籍・卒業生・活動終了のどの欄に載っていたかの記録である。公式サイトとは照合していない。現実の所属・活動状態を答えるときは公式情報で確かめる。キャッシュ内の `fictional_world_note`（卒業生はいない）やCLI出力の世界設定の行は、作成時の会話固有の設定である。別チャットの現実の所属や創作設定へ引き継がず、今回の会話で利用者が採用した場合だけ物語に適用する。スキルの発動条件もキャッシュの有無では変わらない。

## 調査の進め方と権限

対象人物・論点・時点が文脈で明確なら、そのまま調査を進める。明確な範囲を聞き直さない。読取専用の公開ページ取得、ローカル保存・再解析、対象範囲の通常の検証は、依頼のために必要な範囲で実施できる。人物調査だけを理由に外部への投稿・編集・送信は行わない。アクセス制限の回避はしない。

元リンクまたは検索エンジンのサイト指定検索で入口を確認する。文字コードによるURL破損が確認でき、通常の公開HTTPが利用できるときは専用リーダーを選べる。取得済みHTMLの再解析にも使える。記事名のURLはEUC-JPで符号化する。UTF-8で符号化し直したURLはこのwikiでは404になるため、URLの `%xx` をUTF-8として読み直すWeb閲覧ツールでは、日本語の記事名のページを開けないことがある。Python環境で `Temporary failure in name resolution` などの名前解決の失敗が出る場合、その環境からはwikiに接続できない。リーダーを繰り返さず、保存本文で答えて、取得できないページを示す。取得順、並行化、本文の分割幅、作業記録の形式は状況に合わせて決める。同じ失敗を無制限に繰り返さない。

対象者が明確な調査では、人物調査ガイドの『必須の読了範囲』を満たす。これはユーザー指定の品質基準であり、効率化のための断片抽出へ置き換えない。架空の場面を創作する依頼には、[物語の作り方](references/story.md)の『物語用の読了範囲』を適用する。今回の範囲をユーザーが明示的に指定した場合（例: 全文を読んでから書く）は、その指定を優先する。対象外のタレント全員・全ニュース・全商品へ探索を広げない。

## 完了の定義

- 対象ページの一覧と読了状態を把握し、必須範囲の末尾まで実際に読んでいる。創作では物語用の読了範囲を満たしている。取得のみ、検索抜粋のみ、表示が途切れたままでは読了にならない。
- 本文・表・折りたたみ・脚注を確認し、引用に関係する文字破損や呼称の向き、時点の相違を解決するか、未確認範囲を示している。
- 5項目の人物像と根拠・解釈を区別し、実際の質問に必要な内容へ反映している。毎回5項目をすべて最終回答へ列挙する必要はない。
- 現実についての事実主張と、根拠からの解釈を混同せず回答を完成させている。架空世界の内心・台詞・反応・展開は、文脈上明らかな限り導出または物語上の表現として扱う。『創作です』という説明や、公式プロフィール・wiki・呼称一覧を参照した旨の定型注記を末尾へ機械的に追加しない。単なる調査計画や途中の確認で止めない。

取得不能が残る場合は、対象ページと影響を明示して答えられる部分まで仕上げる。創作では、この説明を物語本文に混ぜず、本文の前後に短く分けて書く。『全件読了』とは述べない。不足が結論を左右するときだけ、必要な本文や対象の指定をユーザーに求める。
