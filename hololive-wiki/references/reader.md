# リーダー操作と診断

**v3.9.0+skill.6 / `hololive_wiki_reader.py`**。Seesaa上の対象wikiから1ページを読み、本文・表・脚注・呼称・画像メタデータと診断情報を返すCLIです。隣接する `hololive_adblock.py` が既定の広告判定を担当します。Python 3.9以降を対象とし、標準ライブラリだけを使用します。

対象は `https://seesaawiki.jp/<wiki名>/` のルートと `/d/` 記事です。wiki名には `hololive` が必要で、既定は `hololivetv` です。画像、動画、iframe内の文書、リンク先の記事を自動取得するクローラーではありません。

## 最初に使う

以下はスキルルートを作業ディレクトリとする例。別の場所から使う場合はスクリプトの絶対パスを指定する。全節を毎回読む必要はなく、上の目次から必要な項目を選ぶ。

通常取得では、利用可能なキャッシュがなければHTTP通信を行います。このwikiは絵文字などをUTF-16の数値文字参照の組で記録しているため、本文を読むときは `--surrogate-charrefs utf16` を付けます（既定のままでは絵文字が「�」になります。[サロゲート参照と絵文字](#サロゲート参照と絵文字)）。スキルの `read … --online`・`check-updates` とキャッシュの作成も同じ指定です。

```bash
python3 scripts/hololive_wiki_reader.py --title "ときのそら" --surrogate-charrefs utf16 --all
python3 scripts/hololive_wiki_reader.py --title "ときのそら【呼称一覧】" --surrogate-charrefs utf16 --nicknames --format text
python3 scripts/hololive_wiki_reader.py --title "星街すいせい" --surrogate-charrefs utf16 --find "ソロライブ" --context 1 --format text
python3 scripts/hololive_wiki_reader.py --url "https://seesaawiki.jp/hololivetv/d/%A4%C8%A4%AD%A4%CE%A4%BD%A4%E9" --surrogate-charrefs utf16 --tables --images
```

別wikiでは、URLと一致するwiki名を明示します。

```bash
python3 scripts/hololive_wiki_reader.py --wiki hololivedreams --url "https://seesaawiki.jp/hololivedreams/" --all
```

結果と元HTMLを保存する例です。出力先の親ディレクトリはあらかじめ用意してください。

```bash
python3 scripts/hololive_wiki_reader.py --title "ときのそら" --surrogate-charrefs utf16 --all --output sora.json --save-html sora.html
```

保存HTMLの解析はHTTP通信を行いません。`--url` は記事の同一性、相対リンク解決、wiki範囲の検証に使用します。取得時の `Content-Type` が分かる場合は併記します。

```bash
python3 scripts/hololive_wiki_reader.py --url "https://seesaawiki.jp/hololivetv/d/%A4%C8%A4%AD%A4%CE%A4%BD%A4%E9" --html-file sora.html --content-type "text/html; charset=euc-jp" --surrogate-charrefs utf16 --all --images
```

ローカル索引の検索と、キャッシュHTMLからの索引再構築もHTTP通信を行いません。

```bash
python3 scripts/hololive_wiki_reader.py --search "呼称一覧" --cache-dir .cache
python3 scripts/hololive_wiki_reader.py --rebuild-index --cache-dir .cache --format text
```

検索するには、事前に読み取りで蓄積した索引か、指定した `--index-file` が必要です。索引が空でも、検索のためにページを取りに行くことはありません。

## 入力と通信

### URLとタイトル

| 入力 | 処理 |
|---|---|
| `--url` | 観測したASCIIのパーセント符号化URLを使います。要求時の綴りを保持し、`#` 以降のフラグメントだけを除きます。`%23` は除きません。 |
| `--title` | ローカル索引の完全一致を優先します。一致がなければ、指定タイトルをEUC-JP主体で符号化します。異なる記事パスが同名に一致した場合は `ambiguous_title` で停止します。 |
| `--normalize-title` | タイトル指定時に明示した場合だけ `～` を `〜` へ変換します。索引に元タイトルの完全一致があれば、その観測情報を優先します。 |
| 壊れたURL | U+FFFDやそのUTF-8符号化を含むURLは要求しません。ローカル索引から候補を提示できても、自動選択・自動取得はしません。 |

タイトルのうちEUC-JPで表せる部分は、そのバイト列を保持します。必要な部分だけEUC-JIS-2004拡張を使うため、タイトル全体の再符号化によって `é`、`©`、`®` などのバイトが変わる問題を避けます。円記号・オーバーラインのように往復変換で別文字になる入力も拒否します。表示名から正しいURLを推測して置き換える処理はありません。

対象はHTTPSの `seesaawiki.jp` に限ります。wiki名は1～128文字の英数字・`_`・`-` で、大小文字を無視して `hololive` を含む必要があります。指定wiki以外への遷移、一覧・検索・編集・履歴・差分・添付などの経路は許可しません。ルートと `/d/` に限定する固定の経路検証であり、実行時にrobots.txtを取得して判断する仕組みではありません。

### 取得時の検証

| 項目 | 現行動作 |
|---|---|
| 成功応答 | HTTP 200を要求。Content-TypeがあればHTML/XHTMLのみ、なければ先頭8,192バイトにHTMLらしい開始要素があるか確認します。 |
| リダイレクト | 301・302・303・307・308を1ホップずつ検証し、最大5回。Locationの生バイト由来の情報を保持し、ループや対象外への遷移を拒否します。 |
| Content-Length | 不正な値・異なる値の重複を拒否します。同一表記の数値が繰り返される重複は受け入れます。実際の受信長との不一致を検出します。 |
| 応答境界 | Content-LengthとTransfer-Encodingの併記、Content-Range付きの部分応答を拒否します。HTTP 206も成功扱いにしません。 |
| 圧縮 | identity、gzip/x-gzip、deflateに対応。deflateはzlib形式と生deflateを扱います。zlibとしての完全性検証に失敗した場合も生deflateを試し、成功した形式の終端・残余データ・容量制限を検証します。転送後と解凍後の双方に容量制限を適用します。 |
| 容量 | 既定は各24MiB＝25,165,824バイト。`--max-bytes` で正の整数に変更できます。非常に大きな値（2^63−1など）も指定できます。保存したHTML・解凍後の本文・キャッシュ記録は、上限ぶんの領域を先に確保せず、1MiBずつ読みます。 |
| 通信間隔 | 1回のCLI実行内の要求開始間隔は最小0.5秒。リダイレクトとデスクトップ再取得も含みます。 |
| 時間 | ソケット操作のタイムアウトは既定20秒、通信全体の予算は既定90秒。読み取り・要求の間で予算を確認します。`--timeout`・`--time-budget`・`Retry-After` は10^6秒（約11.6日）を上限に丸めます（それ以上の値は、ソケットの設定で `OverflowError` になるか（Windowsでは約2.1×10^6秒以上、Linuxでは約9×10^9秒以上）、JSONにならない `Infinity` になります）。 |
| 証明書 | Python標準のTLS証明書検証を保持します。検証を無効にするオプションはありません。 |

再試行するHTTPステータスは **408・429・500・502・503・504** です。このほか、受信長の不一致、タイムアウト、接続切断、途中で終わる読み取り、一時的な名前解決失敗など、実装が一時的と判定した通信例外が対象です。すべての5xxや、すべてのネットワーク例外を再試行するわけではありません。SSLエラーと証明書検証エラーは再試行しません。

再試行は既定2回、指定範囲は0～3回です。待ち時間は指数バックオフと有効な `Retry-After` の長い方を採用します。要求された待ち時間を短縮せず、30秒を超えるか残り時間以上なら `retry_deferred` で報告します（それまでの要求回数 `http_requests` と再試行の記録 `retry_history` を付けます）。HTTP 403を理由にUser-Agentを切り替える処理はありません。HTTP 404だけでURL破損と断定することもありません。

HTTP 200にlite用スタイルシートがあり、`#page-body-inner` がない場合は、デスクトップ用User-Agentで再取得する段階へ一度だけ進みます。この段階にも通常の通信再試行設定が適用されます。判定は生バイトで候補を絞りますが、`<link>` 属性内のHTML文字参照でCSSのURLが書かれた場合もパーサで確認します。単純なバイト列検索だけでモバイル応答を見落とさない構成です。UTF-16・UTF-32（バイト順マークまたはNULバイトがあるもの、またはContent-Typeの文字コードで示されたもの）の応答は、デコードした文字列で同じ判定をします。閉じていない `<link` が続くページでも、判定の時間はページの大きさに比例します。

## 文字コードと文字参照

デコードの優先順位は **明示的な `--encoding` → HTTP charset → BOM → HTMLのmeta宣言 → EUC-JP既定** です。meta宣言は先頭65,536バイトから調べます。HTTPとmetaが食い違えば警告します。

EUC-JPを選択した場合はstrict EUC-JP、strict EUC-JIS-2004の順に試します。それでも読めない場合はEUC-JIS-2004で置換し、警告と監査を出します。他の選択コーデックでは、そのコーデックのstrictデコード失敗時に置換します。読めたことだけを根拠に拡張文字の由来を確定することはありません。

| 監査フィールド | 対象と意味 |
|---|---|
| `encoding_audit` | EUC-JP範囲外のバイト単位。NEC系の共通対応との一致、出典側対応未確認、デコード不能を区別し、バイト位置・HTML行などを示します。 |
| `byte_replacement_audit` | 元データから読めたU+FFFDと、今回のデコーダが挿入したU+FFFDを区別します。 |
| `html_reference_audit` | デコード後HTML全体にある、サロゲート・範囲外・NULL・明示的U+FFFDの数値文字参照を数えます。コメントやスクリプトなど本文外も含みます。 |
| `charref_repairs` | 明示的なUTF-16互換処理と、巨大な数値文字参照の等価表記への正規化を記録します。 |
| `structured_replacement_audit` | 表・脚注・リンク・見出し・メタデータ・画像など、表示前の構造化フィールドに残るU+FFFDを監査します。`--images` 未指定の画像フィールドも対象です。 |

本文・HTML全体・構造化フィールドは対象範囲が異なります。同じ元文字が複数表現に現れることもあるため、これらの件数を足して破損した元文字数と扱わないでください。

### サロゲート参照と絵文字

既定の `--surrogate-charrefs html` はHTMLの意味に従います。`&#55357;&#56877;` のようなサロゲート数値参照は、既定ではU+FFFDになります。

このwikiは、EUC-JPで表せない絵文字などをこの表記（UTF-16のサロゲート対）で記録しています。本文を読むときは次のように指定します。スキルの `read … --online`・`check-updates`、キャッシュの作成も `utf16` を使います。2026-09-25に100ページを取得して確かめたところ、既定の指定では26ページで計1,084文字が「�」になり、`utf16` では元のHTMLにある1ページ・2文字だけでした。

```bash
python3 scripts/hololive_wiki_reader.py --title "ときのそら" --surrogate-charrefs utf16 --all
```

`utf16` は隣接する適切なペアを、HTML文書内のテキストと `title`・`alt` 属性で結合する互換モードです。記事抽出前の処理なので対象は本文コンテナだけではありません。URL属性、スクリプト・スタイルの生テキスト、コメントにはこのペア結合を適用しません。元バイト、ハッシュ、元HTML上の文字参照監査は保持します。

129桁以上の10進数値参照は、Pythonの整数桁上限による停止を避けるため、HTMLとして等価な短い表記へ正規化します。これは両モードで必要に応じて行う別処理です。UTF-16互換処理でも、対応が分からない壊れた文字を推測で補いません。

## 本文と構造化データ

### 抽出範囲と節選択

`#page-body-inner` 内に `.user-area` がある場合、その領域と `.footer-footnote` を抽出します。複数の `.user-area` は出現順に結合し、警告します。`#page-body-inner` 自体がなければ `#page-body` を警告付きで試します。`.user-area` が見つからない場合はコンテナ全体が対象になり得るため、`article_selector` と警告を確認してください。

通常の `.user-area` が確認できたレイアウトでは、領域外のコメント欄・広告・編集UIなどは本文に入りません。折りたたみ・非表示指定だけを理由に記事内容を落としません。空の記事と判断するには、明示的な `.user-area` と必要な閉じタグなどの根拠が必要です。画像だけなど文字を抽出できない記事は `no_extractable_text` と区別します。

見出しにはレベル、テキスト、元HTMLの `source_line`、整形本文の `article_line` を付けます。`--section` はパースした見出しに対応する行を使い、本文中の `# ` で始まる文章を新たな見出しとして数えません。完全一致を優先し、なければ部分一致を使います。複数候補なら停止し、選んだ見出しから次の同レベル以上の見出しの直前までを節とします。

表セル内など、独立した見出し行として選べない見出しも構造情報には残ります。その見出しで後続表の節所属を上書きしないため、本文と表・呼称の節対応が一致します。

見出しの中に見出しがある壊れたHTMLでは、外側の見出しの `text` に内側の見出しを含めません（内側の見出しは別の項目になります。本文の行は変わりません）。ページ情報（`page_metadata`）のカテゴリ・タグも、入れ子のリスト項目をそれぞれの項目とし、外側の項目に含めません。保存した実ページ1,149件には、入れ子の見出しも入れ子のカテゴリ・タグもありません（2026-10-02の `3.9.0+skill.6` から。それまでは内側を外側にも含めていたため、入れ子が深いと処理時間と出力が段数の2乗で増えていました）。

`--section` の照合対象は `headings[].text` と同じパース済みテキストです。`--links` や `--format` が変わっても、一致候補と一意性の判定は変わりません。見出しが本文で独立した行を持つかどうかは、整形本文と `article_line` の対応で判定します。

表示対象はまず節で絞り、`--find` を指定した場合はその中の一致行を選びます。`--context` 併用時も **`--start` は一致行の何件目から始めるか**を表します。`--lines` は文脈を含む表示行数の上限です。上限が小さい場合は前方の文脈を減らし、指定した最初の一致行を必ず含めます。飛ばした一致を後続の一致の文脈として再表示しません。

`match_offset` は一致集合内、`selection_offset` は文脈を含む表示行集合内の開始位置です。`more_matches` は表示範囲より後に未表示の一致があるか、`more_after` は表示対象の後続行があるかを表すため、両者は同じ意味ではありません。

`--all` は `--start` / `--lines` を無視しますが、節・検索・文脈の指定は残します。全文を表示するには、検索や節を付けずに `--all` を使います。

### 表と呼称

`--tables` は物理的な行・セル、rowspan/colspan、その元表記、リンク参照、論理グリッドを返します。論理グリッドは各位置から元の行・セルへ対応付ける形式です。

| 制限 | 値 |
|---|---|
| 1表の論理グリッド | 既定・最大1,000,000枠。`--max-grid-cells` で1～1,000,000に縮小可能 |
| 1表の行・列 | 最大50,000行・256列 |
| span属性として扱う整数 | 1～10,000。実際の展開には行・列・枠数制限も適用 |
| 1ページで保持するグリッド | 合計4,000,000枠 |
| 1ページの展開作業予算 | 4,000,000単位。行の確保と試みたspan枠を計上し、失敗した表の消費も戻さない |

セルの中の表（入れ子の表）は独立した表として `tables` に入り、そのセルの `text`・`text_without_footnotes`・`link_ids`・`footnote_numbers` には含めません。セルには中の表の `index` を `nested_tables` で示します。キャプションも同じです。本文の行（`lines`）は従来どおり入れ子の表を含みます。2026-10-01までの `3.9.0+skill.5` は、外側のセルにも中の表の内容を含めていたため、入れ子が深いと出力が段数の2乗で増えていました（4,000段で136 KBの入力から26 MB）。保存した実ページ1,149件には入れ子の表はありません。

ページ全体の2種類の予算は固定です。表の重なり、範囲外span、上限超過などがあれば、該当表の `grid` を `null` にして警告し、物理セルを残します。上限到達は記事全体の失敗を意味しません。グリッドを作れなかった表からは、グリッドに依存する呼称レコードを生成しません。

`--nicknames` は「相手」「呼び方」「呼ばれ方」の列を認識し、span解決後のセルから正規化レコードを作ります。セル全体が `-`・`‐`・`–`・`—`・`―`・`−`・`－`・`ー` のいずれかなら「なし」として空文字にします。`ロボ子ーさん` のような名前の一部は変更しません。

`--section` 使用時の表と呼称は選択した節の範囲です。`--find` や表示行数だけでは構造化表・呼称を絞り込みません。

本文行では、セル内の改行は親の表行を分断しないよう整形します。入れ子表の行、画像alt、インライン脚注本文、span注記、インラインURLにもこの扱いを適用します。元の属性値は画像メタデータ、`rowspan_raw` / `colspan_raw`、`links` / `link_original_hrefs` などに保持します。ここでいう属性値は、パーサへ渡したHTMLの文字参照を展開した後の値です。明示したUTF-16互換前処理も反映されるため、前処理前の元バイトが必要な場合は `--save-html` を使います。

### 脚注、リンク、タイトル

脚注は本文マーカーの `title` 属性と脚注定義を保持し、一致・不一致、定義なし、空定義、未参照定義を区別します。サイト側の脚注区切りとして確認できるコロンだけを除き、本文の句読点・コロンは保持します。空定義も消しません。

`--footnotes markers` はマーカー表示、`inline` は注内容のインライン表示、`off` は認識したマーカーの非表示と構造化脚注出力の省略です。通常のJSON脚注情報は記事全体が対象で、選択本文の参照番号は別フィールドで示します。

脚注一覧（`.footer-footnote`）の行（`li`）は、脚注番号を1つだけ含む一番外側の行をその脚注の定義とし、その中の行は定義の本文に含めます（同じ脚注の別の定義として数えません）。番号を2つ以上含む行は警告して、その中の行を読みます。脚注一覧の中にある脚注一覧は1回だけ読みます（2026-10-01までは、外側の一覧の数だけ同じ定義が入っていました）。

空の脚注マーカーも落としません。マーカーが表示上の空白行にある場合は直前の表示行へ対応付け、本文冒頭で先行行がない場合は最初の表示行へ対応付けます。表示行がない場合は行番号を作らず、脚注情報を保持します。この補正は見出しや通常リンクの行番号には適用しません。

本文中のリンク表示は `--links references`・`inline`・`off` で指定できます。JSONの既定は参照番号、text/mdの既定はインラインです。`inline` はwiki内リンクを `[[タイトル]]` などで示します。リンクの元URL表記と、要求可能なURLの検証は別に保持します。

行番号はリンク表示によって変わることがあります。参照番号の表示では、画像だけのリンク（`<a>` の中が `<img>` だけ）も `[60]` のような1行になりますが、インライン表示ではその行が出ないため、それより後の行番号が小さくなります。2026-09-27に宝鐘マリンのメインページを取得した例では、参照番号910行・インライン907行でした（差の3行はすべて画像だけのリンクの行）。人物別キャッシュの `pages/<ID>.txt` と `check-updates` の比較は、参照番号の表示の行番号です（キャッシュCLIの `read … --online` は、`--links` を付けたときに参照番号の表示になります）。キャッシュと行番号で突き合わせるときは、JSONか `--links references` を使ってください。

選択本文に対応する `links` は、HTMLのリンク要素と本文行の対応から求めます。本文中の `[1]` やURLらしい文字列から推測しません。複数行を占めるリンクは各行へ対応付けるため、一部の行だけを選んでもURLを保持します。

`--links off` は本文のリンク装飾を省略する指定です。選択した本文行に実在するリンクなどの構造化情報まで削除する指定ではありません。`--all-links`、インライン表示、または絞り込みのない全文出力では記事全体のリンクを返す場合があります。実際の範囲は `links_scope` を確認してください。構造化脚注を出す場合、その脚注定義の出典リンクも保持します。

長い外部リンクのラベルでも、インライン表示に出典URLを保持します。

`document_title` は文書のタイトルで、記事の前後にあるSVGなどの `<title>` を混ぜません。`article_title` は記事URLから得た表示用タイトルです。この表示用タイトルから要求URLを作り直すことはありません。取り消し線は `~~…~~` で表し、iframeは存在・参照情報を保持できても内部文書は取得しません。

### 画像メタデータ

`--images` を指定すると、抽出記事内の `<img>` ごとに次の項目を出力します。JSONに加え、text/mdでも一覧を表示します。

| フィールド | 内容 |
|---|---|
| `url` | 記事URLを基準に解決したURL。解決不能なら `null` |
| `src` | HTMLパーサが読み取ったsrc属性。HTML文字参照は通常の属性解析で展開済み |
| `alt` | パーサが読み取った代替テキスト。指定したUTF-16互換前処理も反映 |
| `width` / `height` | HTML属性の指定値。画像の実寸を測定した値ではない |
| `srcset` | 属性値を保持。候補の選択や画像取得はしない |
| `source_line` | 元HTML上の行番号 |

**画像一覧は記事全体が対象です。`--section`・`--find`・表示行数でも絞り込まれず、`images_scope` は `whole_article` です。** `total_images` は記事全体の件数で、`--images` 未指定でも出力します。詳細一覧は指定時だけ出力します。

壊れた画像URLは元の `src` と警告を残し、記事全体の解析を継続します。画像属性内のU+FFFDも構造化監査とキャッシュ品質判定に含めます。画像ファイルのダウンロード、画像認識、OCR、動画・外部埋め込みの取得は行いません。

## 広告判定

既定の `--ad-filter strict` は、確認済みの広告枠・コメント投稿などの記事外要素を解析中に除き、選択前の記事全体の本文・リンク・脚注・表・画像alt・埋め込み参照などに広告配信ホストのURLが残れば `ad_content_detected` で停止します。記事の一部だけを `--find` / `--section` で選んでも判定範囲は縮まりません。広告配信ホストのURLを資料として文章中に引用した記事も停止し得ます。

必要な文章が止められた場合は、理由と範囲を確認し、`--ad-filter report` で広告枠を除いた本文を**警告付きで**取得します。`--ad-filter off` はこの解析・残存URL判定を無効にした旧版相当の解析で、広告要素が混じり得ます。`report` / `off` の出力を無条件に無広告とみなさず、`ad_filter` の除外件数、`output_scan` と警告を確認します。既知ホスト以外を含むあらゆる広告を検知できる機能ではありません。

```bash
python3 scripts/hololive_wiki_reader.py --url "https://seesaawiki.jp/hololivetv/d/%A4%C8%A4%AD%A4%CE%A4%BD%A4%E9" --ad-filter report --all
```

どのモードも画像・スクリプト・iframeの中身は取得せず、HTML取得先のwiki範囲検証を維持します。通常のページで `strict` が通るなら既定のまま使用します。

## キャッシュと索引

### ページキャッシュ

キャッシュは `--cache-dir` 指定時だけ有効で、既定は無効です。1応答を元HTMLのbase64・SHA-256・取得メタデータ付きのJSONとして原子的に保存します。通常の再利用ではURL、要求User-Agent、リーダー版、TTL、サイズ、チェックサム、HTMLと記事コンテナを検証し、保存時の品質ラベルだけを信用せず再解析します。再解析は、読み取りと同じ `--ad-filter` と `--max-grid-cells` で行います（`report`・`off` で保存したページは、同じ指定で再利用できます。指定を省くと既定の `strict` で検査するため、`strict` で受け入れられないページは再利用しません）。TTLの既定は21,600秒＝6時間です。

URLのクエリは通常のHTTPキャッシュでは区別します。パーセント符号化の16進文字の大小は同一視します。現行版と異なるリーダー版の記録は通常のページ再利用に使いません。旧v3.8.3のHTMLが残る場合、`--rebuild-index` で観測済みタイトルを再構築できても、そのHTMLを現行版のページ結果として通常再利用するわけではありません。`--refresh` はキャッシュを読まず新規取得します。`--encoding` 指定時も通常キャッシュを再利用・保存しません。

| 方針 | 動作 |
|---|---|
| `--cache-policy clean`（既定） | バイトデコードの置換、本文・構造化フィールドのU+FFFD、文字参照の結合・巨大参照の前処理があれば保存・再利用を見送ります。 |
| `--cache-policy diagnostic` | これらの診断がある元応答も警告付きで保存・再利用できます。診断は再計算し、破損の原因や恒久性を確定しません。 |

どちらの方針でも、必要な記事コンテナが閉じていない応答、モバイル不完全レイアウトなどを正常な再利用対象にしません。`clean` は「警告が一切ない」ことや内容の正しさを保証するラベルではありません。

保存時には `requested_title`・`title_used`・`title_source`・`title_url_source`・`title_observed_urls`・`title_encoding`・`title_normalized` など呼び出しごとの情報を除きます。読み込み時には応答由来の許可されたキーだけを再利用し、以前のタイトル解決情報や、未知の `operation` / `search_results` が後続実行の来歴・結果表示へ混入することを防ぎます。

`fetch_warnings` は文字列のリストとして検証します。再利用するメタデータ全体がUTF-8へ符号化できることも確認し、JSON内の単独サロゲートなどで出力全体が壊れる記録は不正キャッシュとして扱います。破棄する未知のキーに不正値があるだけで、正常な再利用対象のメタデータまで拒否することはありません。

保存用一時ファイルの接頭辞を短くし、保存失敗時にはOS由来の理由を警告へ含めます。ページを読めたもののキャッシュ・通常索引だけ保存できなかった場合は、その違いを報告します。

### タイトル索引と再構築

索引は読み取ったHTMLで観測したリンクと、正常に解析したページ自身のURLを蓄積します。通常読み取りでバイトデコードに置換が発生したHTMLは索引収集に使いません。索引のためのseedページ取得はありません。

タイトルの同一性は記事パス基準です。`?keyword=…` などの表現差は別記事として重複登録せず、観測URLの来歴として保持します。索引は最大4MiBです。既定の保存先は `--cache-dir` 内の `titles.json`、別wikiでは `titles-WIKI名.json` です。`--index-file` で独立した場所を指定できます。別wikiに属する索引は混ぜず、上書きしません。

`--rebuild-index` はキャッシュディレクトリ直下の所定形式のJSON記録を検証し（`--ad-filter`・`--max-grid-cells` の指定で再解析します）、保存HTMLからリンクを再収集して**既存の有効な観測へ追加**します。通常キャッシュでは使わない旧リーダー版やTTL切れの記録も、この明示的なオフライン操作では対象にできます。別wiki、不正記録、バイト置換を伴うデコード、不完全な記事などは除外し、件数と理由のサンプルを報告します。

再構築は既存索引を消して作り直す操作ではありません。削除されたキャッシュや検証に失敗した記録だけを根拠に、既存の観測を削除しません。結果をまとめて保存するため、再構築時の保存失敗や索引サイズ超過で既存ファイルを途中の内容へ置き換えません。過去の観測は、リンク先の現在の存在・公開状態・内容の確認を意味しません。

索引の `observed_on`（観測元の来歴）は文字列かつUTF-8で表せる値として検証します。不正な来歴を含むローカル索引は警告して無視し、後の検索結果出力や索引保存まで不正値を持ち越しません。

**v3.8.3以前は別のリーダー版です。そのページキャッシュは、現行版の通常読み込みでは新規取得が必要です。** `--rebuild-index` で検証可能な旧スナップショットから観測索引を維持することはできます。版の異なるキャッシュを現行版として扱うために版文字列だけ書き換えることはしません。キャッシュ削除・サイト巡回はこのCLIに内蔵していません。

`python3 scripts/hololive_wiki_reader.py --help` でも各指定を確認できます。

| `--title` | 読み取る正確なタイトル |

| `--start` | 1以上、既定1。検索なしでは節内を含む本文選択の開始位置。`--find` ありでは一致行の開始件数。文脈行は数えない |
| `--lines` | 最大表示行数、1以上。既定80。索引検索では最大結果件数 |

## 出力とエラー

| 分類 | 主なJSONフィールド |
|---|---|
| 実行と取得 | `reader_version` `wiki` `url` `requested_url` `source` `fetched_at` `parsed_at` `http_status` `http_requests` `from_cache` `html_bytes` `wire_bytes` `html_sha256` |
| タイトル指定 | `requested_title` `title_used` `title_source` `title_encoding` `title_normalized` など。実行経路に応じて出力 |
| 文字 | `encoding_declared` `encoding_meta` `encoding_source` `encoding_used` `decode_lossy` `replacement_characters` と各監査 |
| 記事 | `page_title` `document_title` `article_title` `article_selector` `article_integrity` `article_state` `article_content` `lines` `headings` |
| 選択 | `total_lines` `returned_lines` `more_before` `more_after` `total_selection_lines`、指定時の `section`・`match_offset`・`selection_offset`・`total_matches`・`more_matches` |
| 構造 | `tables` `nicknames` `footnotes` `footnote_diagnostics` `links` `link_original_hrefs` `page_metadata` `images` `ad_filter` |
| 範囲・制限 | `tables_scope` `nicknames_scope` `links_scope` `images_scope` `grid_limits` |
| 件数・診断 | `total_tables` `total_images` `total_links` `known_articles` `warnings` `replacement_lines` `article_replacement_characters` `structured_replacement_characters` |

各項目は入力経路・オプションにより省略されます。たとえばローカルHTMLは `source="local_html"`、`http_requests=0`、`fetched_at=null` で、現在のHTTP成功を示すものではありません。キャッシュは `source="cache"` と元の取得情報を持ちます。ローカル索引検索・再構築も `http_requests=0` です。`http_requests` はリダイレクト・再試行・デスクトップ版の再取得を含む要求の回数、`retry_history` は待機した再試行の記録（デスクトップ版を再取得したときは最初の取得の分を含む）、`redirects` は最後の応答に至ったリダイレクト、`layout_fallback` はモバイル版が不完全でデスクトップ版を取得したときの記録です。取得に失敗した場合も、エラーの詳細に `http_requests` と `retry_history` が付きます（取得の前に失敗した場合を除く）。

textとmdは同じ描画を共有し、行番号、構造化一覧、警告を含みます。md専用の行番号除去やJSON一覧のコードフェンス化は行いません。標準出力・標準エラーは、引数の解析より前に可能ならUTF-8へ再構成します（`--help` と引数の誤りの表示も含みます）。再構成できないストリームではそのまま処理を続けます。パイプ切断は出力時と遅延フラッシュ時の両方で扱います。

通常成功は終了コード0、読み取り・処理失敗は1で、JSON形式の `error`・`error_code` と詳細を標準エラーへ出します。通信の失敗（`network_error`）の詳細には、例外の種類 `exception`、理由 `reason`、要求回数 `http_requests` と再試行の記録があります。`retry_deferred`・`time_budget_exceeded`・`mobile_layout`、および取得のあとに起きた誤り（本文が空など）にも `http_requests` が付き、`check-updates` はこれを足します（取得しなかった場合は付きません）。urllibが例外を包んだ場合は、その種類 `reason_exception` も付けます（名前解決の失敗は `gaierror`、タイムアウトは `TimeoutError`（Python 3.9では `timeout`）、接続の拒否は `ConnectionRefusedError` など）。理由の文言はOSによって違うため、失敗の種類は `reason_exception` で判断してください。CLI引数の誤りはargparseの使用法エラーです。キャッシュ・索引の保存警告だけで本文読み取りが失敗したとは限りません。`--output` は通常結果の保存先であり、エラーJSONの保存先ではありません。

`--output` / `--save-html` または明示的な索引再構築の保存失敗は、`output_write_failed` と要求したパス・OS由来の理由を報告します。索引再構築の失敗時には、得られた `rebuild_index` レポートもエラー詳細へ付けます。一時ファイル名だけを利用者に返して目的の出力先が分からなくならないようにします。

## 仕様上の限界

- これは1ページの読み取り結果です。リンクされていないページ、未読ページ、サイト全体の網羅性を保証しません。
- 必要なコンテナの閉じタグがあっても、転送・意味・編集内容の完全性を証明するものではありません。未閉の場合は診断付きで回収内容を残すことがあります。
- U+FFFDや出典対応未確認の拡張文字を推測で直しません。該当する名前・引用・表セルは診断と原文を確認してください。
- コメント抽出、広範な似た文字の一括正規化、画像認識、OCR、JavaScript実行は実装していません。
- 画像のURLはメタデータです。参照先へ接続せず、存在・種類・安全性・実寸を検証していません。
- 広告判定は既知の配信ホストとHTML構造の規則です。資料としてのURL記載も既定で拒否されることがあり、未知の広告を完全に識別する保証もありません。必要な本文は診断を見て `report` で確認してください。
- グリッド上限は展開処理の予算であり、プロセス全体のメモリ上限ではありません。物理セルと本文は別途保持します。
